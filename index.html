memoir

memoir · /ˈmemwɑːr/ · noun 回忆录——一份被记住、被讲述的记录，不是一堆原始照片。这个 skill 想做的，就是把一次旅行变成这样一本。

一组散乱的旅行照片，交给 agent：EXIF 和 GPS 搭骨架，策展做取舍，叙述记住当时，现场写的 HTML 决定它最后长成什么样。

The Product

不是相册导出，是一条完整的编辑流水线。

memoir 把工作拆成清楚的几段：先在本地读照片的元数据，再做地理聚类和品质预检，然后交给 agent 做视觉策展、写中文叙述、设计页面。交付的不是 dashboard，也不是模板站——是一份双击就能打开的旅行回忆 HTML。

从两千张里，留下真正能讲故事的那些。

模糊、截图、重复连拍、票据、无意义的转场都被挡在作品外。每张入册的照片都要能回答一句：它为什么值得出现？

  1. 01EXIF 提取：时间、GPS、相机和文件状态。
  2. 02地理聚类：按日期、坐标和移动距离把行程切成段。
  3. 03品质预检：模糊、曝光、截图、重复、连拍。
  4. 04策展与写作：旅行标题、每日叙述、照片 caption。
  5. 05现场设计：按这次旅行的气质生成一份独立 HTML。

The Skill

一切从读懂你这趟旅行开始。

memoir 不是一个自动相册导出器。开工前 agent 会先问几个问题——这趟旅行是什么感觉？照片是手机拍的还是相机？你想要一本私人日记，还是一篇能发出去的游记？然后从设计池里挑两三个方向让你选。如果池子里没有合适的，agent 可以照你描述的气质，现场写一个新方向。

Privacy
本地优先，AI 策展。

EXIF 解析、缩放、HTML 后处理在本地完成；GPS 坐标发往 Nominatim 查地名；照片会传给多模态大模型做视觉策展和叙述写作——这是流水线的必要环节，但照片不会上传到图床或用于模型训练。

Curation
先删，再写。

contact sheet 一次读完全局，机器预检加上视觉判断——别把网页变成照片垃圾桶。

Design Pool
NEVER converge。

大画册、旅行手帐、宽银幕、暗房、Zine、极简白——每个方向都有自己的布局 archetype，不是换一套 CSS 配色。

Delivery
单文件交付。

照片 token、Leaflet、JSON 数据由后处理脚本注入；最终 HTML 拖进浏览器就能看，也能发布到静态托管。

Gallery

同一组京都照片，六种完全不同的读法。

这些变体用的是同一批精选图，但每个页面的结构、照片处理、字体和节奏都不一样。这里展示的是 skill 的设计方向池——不是换皮的 CSS theme。

示例作品

京都三日，坂道与黄昏。

30 张合成的京都旅行照片，精选 23 张，生成三天的叙述、一张地图和灯箱，最后是一份自包含的 HTML。这是 memoir 的基准样例，也是上面那六个画廊变体的共同母本。

Install

把 memoir 装进你的 agent 工作流。

仓库根目录负责展示和 GitHub Pages；真正可安装的内容在 skill/ 目录。复制或 symlink 过去，agent 就会照 SKILL.md 跑完从照片到 HTML 的整条流程。

快速安装

适用于 Claude Code，也适用于任何能读取本地 skill 目录的 agent 环境。

git clone https://github.com/EricJiang0423/memoir.git
cd memoir
ln -sf "$(pwd)/skill" ~/.claude/skills/memoir
pip install -r skill/requirements.txt

产品承诺

  • 本地优先 · AI 策展照片传给多模态大模型做策展和叙述，但不上传到图床或用于模型训练。
  • 有审美纪律先策展、再叙述、再设计——不做模板相册。
  • 可复现流水线脚本之间只通过 JSON 文件交接，方便调试和二次开发。
  • 静态可部署最终作品和这个首页都能直接放上 GitHub Pages。
