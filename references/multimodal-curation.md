# multimodal-curation · Codex 多模态策展协议

curate.py 已经把照片的品质指标（模糊、曝光、去重、连拍）预检完毕并生成了 contact sheet。你的任务是用**一次 Read 调用**读完 contact sheet，结合机器指标做出最终的视觉策展决策。

## 为什么要用 contact sheet

传统流程：Read 每一张入册照片 → 120 张 = 120 次多模态调用 → 慢且贵。

V1.3 流程：curate.py 生成一张 contact sheet（缩略图网格 + ID 叠加 + 色边标记）→ 你**一次 Read** 读完 → 在同一个多模态窗口中并排对比所有照片 → 高效做 keep/maybe/reject 决策。

## Contact sheet 怎么看

curate.py 生成的 contact sheet 是一张 JPEG 网格图：

```
每格 = 200px 缩略图 + ID 标签（#0001） + 色边标记
绿色边 = 机器推荐 keep
黄色边 = 机器标记 maybe（曝光问题等）
红色边 = 机器推荐 reject（模糊 / 截图 / 不可用）
```

**你的视觉策展可能覆盖机器建议**——机器的模糊/曝光指标准，但不会理解"这张模糊的照片其实是情感峰值"或"这张曝光过度的背影是唯一有她的照片"。你有权 override。

## 策展维度（按优先级）

### 1. 构图质量

正面信号：三分法、引导线、对称、负空间、画面有明确主体
负面信号：主体不确定、地平线严重歪斜（非故意）、关键元素被切、画面杂乱无章

### 2. 情感/叙事价值

正面信号：捕捉到一个瞬间（笑/凝视/转身）、人和环境有关系、光线有情绪
负面信号：pose 僵硬、无人在画面中且无地点特征、信息量为零

### 3. 人物表现

正面信号：自然的侧脸/背影、与环境互动（看书/指路/拍照）、群像有层次
负面信号：表情不佳、闭眼、对着镜头比手势（除非只此一张）

### 4. 粗心废片

直接标记 reject：
- 手指/脚/腿误入画面边缘
- 口袋误触（全黑 + 运动模糊 + 布纹）
- 镜头盖未取下
- 极端倾斜（180° 翻转等）
- 纯白/纯黑空片

### 5. 截图与 UI

直接标记 reject：
- 可见 UI chrome（电池图标、时间、导航栏、通知栏）
- 二维码、菜单、票据、证件的屏幕拍摄
- App 界面截图

### 6. 去重与连拍

curate.py 已分组。你的判断：
- **重复组**（pHash Hamming < 10）：通常只留 1 张——选构图/曝光/表情最好的
- **连拍组**（pHash Hamming 10-20，同分钟）：最多留 2-3 张——如果它们确实捕捉了不同瞬间（如跳跃序列、表情变化序列），不要因为"差不多"全删

### 7. 同一地点的多样性

在同一地点的 photos 里，检查：
- 是不是 5 张全是同一个角度？→ 只留最好的 1-2 张
- 宽景 / 中景 / 细节 / 人物 是否都有？→ 多样性重要
- 是否有一张"非典型"的照片（细节/光影/意外角度）比"标准旅游照"更有记忆点？

## 输出决策格式

读完 contact sheet 后，用结构化文本输出你的策展决定：

```
Day 1 · 2024-03-01 · 那覇市

  国際通り（12 张 → 保留 4 张）：
    photo_0001: keep — 清晨光线穿过拱廊，唯一的空街照，有"开场"感
    photo_0002: reject — 与 0001 几乎相同角度（重复组 #1），但过曝
    photo_0003: keep — 花店门口的老太太，人与环境互动自然
    photo_0004: reject — 模糊（机器已标）+ 手指入画左下角
    photo_0005: reject — UI 截图（机器已标），地图导航页
    photo_0006: keep — 街角的猫，唯一一张"非地标"的有趣细节
    photo_0007: reject — 重复组 #2，与 0006 同猫但构图更乱
    ...

  首里城公園（16 张 → 保留 5 张）：
    ...
```

关键：每个 reject 决策都必须有理由（哪怕只有一个词），这样用户 audit 时可以理解取舍逻辑。

## 机器建议的反驳规则

curate.py 的机器建议不是最终决定。以下情况可以 override：

| 机器说 | 但你可以保留，如果 |
|--------|-------------------|
| `reject_blurry` | 模糊是故意的（追焦/拖影/艺术失焦）或这是唯一一张有某个人的照片 |
| `reject_screenshot` | 几乎不 override——截图在旅行日记中没有叙事价值 |
| `maybe_overexposed` | 过曝是高调风格的、或是雪地/白色建筑本身的自然表现 |
| `maybe_underexposed` | 欠曝是剪影/逆光/夜晚氛围的一部分 |
| `keep`（机器觉得没问题）| 但构图单调、无主体、无叙事 → 你可以 reject |

## 超大照片集（> 500 张）的处理策略

单张 contact sheet 超过 ~800 张缩略图时会触发 OOM。V1.3 的分天策略：

### 方案 A：分天 contact sheet（推荐）

```bash
# 不要一次生成全量 contact sheet——每张 120px 缩略图 × 2000 张 → 内存爆炸
# 改为：生成分天 contact sheet
python3 -c "
import json, cv2, numpy as np
# ... 对每个 day 单独生成 contact_{date}.jpg ...
"
```

每张分天 contact sheet 控制在 800 张以内（约 100 行 × 8 列 = 12,000px 高以内）。

### 方案 B：全自动策展（当多模态不可用时）

如果 agent 不支持读图，或照片量太大无法逐张视觉策展，降级为全自动模式：

1. 用 `curation_manifest.json` 的机器指标做初筛
2. 对每张待选照片按 `blur_score` 降序排列
3. 每地点/每天取 top N（N = 目标入册数 / 地点数），同时控制时间多样性（同分钟最多 3 张）
4. 去重组只留 1 张（选最清晰的），连拍组只留 2 张（首尾）
5. 标记 `source_photo_count` / `sampled_photo_count`

### Contact sheet 内存限制

curate.py 生成 contact sheet 时的经验阈值：

| 照片数 | thumb_size | grid_cols | 内存峰值 | 建议 |
|--------|-----------|-----------|---------|------|
| < 200 | 200px | 6 | ~200MB | 一次生成 OK |
| 200-800 | 120px | 8 | ~400MB | 可以，注意监控 |
| 800+ | — | — | OOM | 分天生成或跳过 |

## 配合 art-direction.md

策展决策输出后，回到 `references/art-direction.md` 做：

1. 把 reject 的照片从 `diary_data.json` 的 `locations[].photos[]` 数组中移除
2. 更新 `source_photo_count` / `sampled_photo_count`
3. 如果地点聚类不稳定，降级为视觉章节（如「水巷与转角」「罗马的重力」）
4. 为每张保留照片准备 caption 观察点
